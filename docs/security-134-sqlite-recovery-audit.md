# SECURITY-134 — Disposable SQLite contention and crash recovery

**Production: NO-GO.** Adds `.github/scripts/test-security-134-sqlite-recovery.py` to offline CI. Tests 12 independent processes racing for one scoped sequence with distinct digests (exactly one winner), replay and digest reuse after process restart, later valid sequence, an uncommitted transaction interrupted with `os._exit(17)` followed by rollback verification and retry, six independent scopes, `PRAGMA integrity_check`, head consistency, and fail-closed handling of a corrupted database file.

The tests use only Python standard library, isolated temporary SQLite databases, and SECURITY-130's synthetic worker. They **do not** cryptographically verify each process request: the SECURITY-130 `verified=True` switch remains a synthetic test fixture. SECURITY-132/133 separately exercise the signature chain; this test focuses on the transactional storage boundary. Crash simulation is a single local process termination, not a power-loss/fsync or distributed recovery guarantee. It does not test networked databases, production Supabase, backups, trusted timestamps, or production readiness. PR #274 remains Draft, no merge or deployment.
