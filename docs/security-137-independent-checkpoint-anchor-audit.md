# SECURITY-137 — Independent signed latest checkpoint anchor (offline)

**Production: NO-GO.** `security/local/security137-independent-anchor.cjs` introduces a domain-separated Ed25519-signed anchor binding an externally supplied positive epoch to a SHA-256 fingerprint of the canonical SECURITY-136 signed checkpoint payload. The verifier requires (1) a valid signed checkpoint, (2) a separately verified signed anchor, (3) fingerprint equality, and (4) exact match against an independently pinned trusted minimum/latest epoch. Tests reject old checkpoint with new anchor, old signed checkpoint+anchor against a newer pinned epoch, changed anchor fields, invalid signature, revoked authority and mismatched epoch.

**Critical trust boundary:** the trusted latest epoch is supplied by the caller as a synthetic fixture; there is **no independent persistence or trusted monotonic epoch service**. If the attacker can roll back the database, checkpoint, anchor and caller-supplied epoch together, the fixture accepts the old state; a regression test demonstrates this. Anchor and checkpoint keys are generated in tests, not trusted production issuers. This is not an operational external audit log, timestamp service or safe production restore gate. No Supabase access, writes or migrations, no CORE 4.2 changes, no merge or deployment. Keep PR #274 Draft.
