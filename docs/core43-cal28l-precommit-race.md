# CAL-28L — precommit archive re-verification

CAL-24 now verifies signed CAL-18B archive evidence a second time after temporary receiver pin is fsynced and immediately before renaming the receiver pin. This detects a class of mutations occurring between initial verification and durable pin update. Regression tests inject changes deterministically at the `temp_fsynced` hook: tampering with archive bytes and swapping the digest-named archive directory. Both must fail closed without changing the pin, leaving a lock, or leaving a temporary pin. Stable evidence must still advance normally.

**Limitations:** Deterministic injection is not an exhaustive multi-process race test. A hostile writer can still modify files after the second verification, during its reads, or before the rename. Parent directory traversal remains pathname based; double verification is not a cryptographically immutable snapshot or directory-level locking. Next steps require immutable/trusted archive snapshots or appropriate OS-level isolation and adversarial multi-process tests. The timestamp authority remains synthetic, not independently proven. No production CORE 4.2 changes, Supabase writes, merge or deployment.
