# CORE43-CAL-28C — evidence-gated receiver approval (offline)

Use `node scripts/core43_cal28_approved.cjs RECEIVER_PIN TRANSFER_JSON TRUSTED_PUBLIC_PEM WITNESS_ID OPERATOR_APPROVED_HEAD ARCHIVE_ROOT` for the new **evidence-gated** advancement path. The receiver independently supplies its trusted key, pin, approval hash, and archive root. It first requires CAL-25 clean preflight, CAL-22 valid signed history, CAL-18B verification of **every** referenced archive, and matching operator-approved head; CAL-24 rechecks history and approval under its writer lock before atomic pin replacement.

**Important limitations:** The old `core43_cal24_pin.cjs` CLI and API remain available and can advance without archive verification; therefore evidence verification is **not yet mandatory across all paths**. This new entrypoint is an opt-in hardened path only. A positive test with real synthetic RFC3161 archives and a concurrent evidence mutation/race test remain to be added. Archive root must be trusted and immutable during verification/commit; this wrapper does not hold archive filesystem locks. Operator approval is not cryptographically authenticated. Do not treat this as pilot authorization. No live collection, Supabase writes, merge, deployment, or production CORE 4.2 changes.
